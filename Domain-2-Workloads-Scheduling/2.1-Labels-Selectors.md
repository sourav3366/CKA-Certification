# 2.1 Labels & Selectors

## 1️⃣ What is this?
Labels are key-value pairs added to Kubernetes objects for identification and grouping.  
Selectors allow you to filter, match, and operate on objects based on their labels.

---

## 2️⃣ Important YAML

### Add labels to a Pod
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
  labels:
    app: nginx
    env: dev
spec:
  containers:
    - name: nginx
      image: nginx
```
### Deployment with labels & matchLabels selector
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-deploy
  labels:
    app: web
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
        tier: frontend
    spec:
      containers:
        - name: nginx
          image: nginx
```
### Service selecting Pods using labels
```yaml
apiVersion: v1
kind: Service
metadata:
  name: web-svc
spec:
  type: ClusterIP
  selector:
    app: web
    tier: frontend
  ports:
    - port: 80
      targetPort: 80
```
Note: Service only sends traffic to Pods whose labels match all keys in selector.

## 3️⃣ Important Commands
### View labels
```
kubectl get pods --show-labels
kubectl get nodes --show-labels
```

### Add or modify a label
```
kubectl label pod nginx-pod env=prod --overwrite
```

### Remove a label
```
kubectl label pod nginx-pod env-
```

### Filter by labels (selectors)
```
kubectl get pods -l app=nginx
kubectl get pods -l 'env in (dev,prod)'
kubectl get pods -l 'env notin (prod)'
kubectl get pods -l 'app,env'        # has both labels app and env
```

### Select multiple labels
```
kubectl get pods -l app=web,tier=frontend
```

### See labels from YAML (describe)
```
kubectl describe pod nginx-pod | grep -i labels
```

### Imperative commands using labels
```
kubectl run test --image=nginx --labels="app=test,env=dev"
kubectl expose pod test --port=80 --labels="exposed=yes"
```

## 4️⃣ Common Mistakes (GOTCHAS)

❗ selector.matchLabels must match pod template labels exactly or Deployment will create 0 pods.

❗ Services do NOT select Pods automatically; labels must match.

❗ Changing labels may break Service → Pod connectivity.

❗ matchLabels uses AND logic, not OR.

❗ You cannot use matchExpressions inside Pod template labels (only selectors).
